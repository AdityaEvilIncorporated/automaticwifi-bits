Setup by platform

macOS

Unzip the archive. Because the app is unsigned, Gatekeeper will block it on first launch: right-click → Open the first time. Then run ./autowifi setup and ./autowifi autostart on in Terminal. Keychain may ask once per update: choose Always Allow.

Windows

Unzip the archive. If SmartScreen appears, click More info → Run anyway. Run autowifi.exe and use the tray menu Set ID and password… (autowifi setup also works in a terminal).

Linux

Extract with tar -xzf autowifi-linux-*.tar.gz, then run ./autowifi setup and ./autowifi autostart on. The tray icon requires AppIndicator support; without a Secret Service keyring, credentials are stored in a mode-600 file.

Android

Download the APK, allow Install unknown apps for your browser, open the app, enter your ID and password, allow notifications, and accept the battery optimisation prompt (recommended).

iPhone (iOS)

Follow the iOS Shortcut Guide on GitHub to set up a Personal Automation for campus Wi-Fi.

Troubleshooting

If login fails because the portal changed, run autowifi capture while on campus. It prints the portal form fields and TLS details (never values).

Campus verification checklist

  • autowifi capture while the portal shows: portal fields match config defaults, action is /.
  • Certificate: "TLS verified by OS trust store: yes" on macOS, Windows, and Linux; Android logs the same.
  • Wrong-password behaviour: wrong password → one notification, no retry storm; right password → silent login.
  • 1-hour keepalive: session survives > 1 hour with keepalive.
  • SSIDs: campus SSID names written into ios/SHORTCUT_GUIDE.md; Shortcut tested on an iPhone.
  • If any field differs: update config defaults and re-release.
